## Edit sessions (preferred for a drag or a grouped inspector edit)

```ts
const started = store.beginTransform(objectId);
if (!started.ok) return;
const token = started.value.token;

// Each pointer update: supply a complete transform, not a delta.
store.previewTransform(token, nextTransform);
// Release:
store.commitTransformEdit(token);
// Or Escape / tool switch / component unmount:
store.cancelTransformEdit(token);
```

Use getTransformEdit() and subscribeTransformEdit() for temporary preview data. Render its after transform only for the matching object; when it becomes null, discard that override and use the current committed document. Preview notifications are separate from normal document notifications. Saving always uses getSnapshot().project, never preview state.

A new begin replaces the previous session. Tokens reject late pointer events after cancellation, project loading, deletion, addition, direct transform commits, undo or redo. Invalid previews cancel the session rather than committing the previous valid preview accidentally. Rejected unrelated edits and rejected project loads leave an existing preview alone. No-op commits finish the session without adding history. UI selection/tool changes and Escape must call cancelTransformEdit; mouse and gizmo wiring remain step 3.

## Deletion

Call store.deleteObject(objectId). A success returns the removed object in value; errors have the same path/message shape as transform errors. Deletion removes the object, its hotspots and their click interactions in one command. Undo restores all three lists with their original IDs, spelling and order; redo removes them again. Other v2 content or hierarchy references still prevent deletion if they would dangle. The editor's Delete selected button uses this method.

Adding or deleting a hotspot and changing interactions also enter the shared undo history. Deleting a hotspot removes its click interactions in the same step. Candidate scenes are validated before publication, and unchanged interaction lists do not consume an undo step or clear redo.

## Undo after refresh

Browser autosave captures `getSnapshot().project` and `getRecoveryHistory()` together before awaiting storage. IndexedDB writes both in one transaction with the existing revision checks. Recovery passes the checked history as the third argument to `loadProject`; ordinary file imports omit it and start with empty history. Exported JSON still contains only the project.

History uses the same whole-project snapshots as `asset-pipeline`: each entry retains the complete document and active scene ID. Object, hotspot and interaction edits affect the active scene, preserving all other scenes, viewpoints, groups, components and rules. `switchScene` changes the current view without consuming an undo step. Undo returns to the recorded scene; recovery also retains the last viewed scene.

Recovery keeps `asset-pipeline`'s version-1 envelope. Its `documents` field contains authoritative whole-project snapshots and the active scene ID; the top-level object lists and optional `views` field are compatibility copies for the first scene. It keeps at most 100 edits and trims the farthest entries from every copy together to meet the 20 MiB serialized-history budget. The earlier, uncommitted scene-only version-2 implementation is not used.

Each restored document goes through the project validator. Project IDs, active scenes and compatibility copies must agree, and the current document must match the saved project. Older object-only history and single-scene v2 viewpoint history are still accepted and upgraded to full documents by the store. Missing history is supported. Invalid history is skipped with a warning while the valid project is recovered; a mismatched project/history pair is rejected before saving.

The committed compatibility fixtures were generated by the original `asset-pipeline` implementation at `bad2ff2458b69bc4d30f250b541df1b85fad0012`. They cover both document and viewpoint envelopes. This aligns the history format; portable project-schema integration remains separate. An older branch reader that does not support the PR's hotspot/interaction fields still needs that schema integration before reading projects containing them.

Only completed edits are saved. The existing autosave waits two seconds after editing; wait for **Saved in browser** (and no Saving indicator) before refreshing. Refresh cannot recover history from backups created before this feature existed. Browser storage belongs to this browser profile and site origin.

Checks: `npm run test:unit` and `node tests/history-recovery.check.mjs <dev-server-url>`. The browser script uses a fresh isolated context and supports the same `PLAYWRIGHT_MODULE` / `PLAYWRIGHT_CHANNEL` overrides as the other browser checks.
